Penjelasan Arsitektur & Implementasi React

Detail penerapan React Routing, State Management, Data Fetching, Custom Hooks, dan struktur folder pada aplikasi TokoKita.

1. Routing dan Navigasi (React Router)

Aplikasi menerapkan client-side routing menggunakan react-router-dom sehingga perpindahan antarhalaman berjalan mulus tanpa memuat ulang halaman penuh (full page reload):

  • Nested Route: Seluruh halaman utama dibungkus di dalam layout induk MainLayout menggunakan komponen <Outlet /> agar navbar, footer, notifikasi toast, dan tombol kembali ke atas tetap konsisten.
  • Dynamic Route: Rute /produk/:id membaca parameter ID produk dari URL melalui useParams() untuk menampilkan rincian tiap produk.
  • Halaman Lengkap: Terdiri dari 7 rute utama, yaitu Beranda (/), Katalog Produk (/produk), Detail Produk (/produk/:id), Favorit (/favorit), Keranjang (/keranjang), Tentang (/tentang), dan halaman fallback 404 (*).

2. State Management & Context API

Pengelolaan state dibagi berdasarkan cakupan dan fungsinya untuk menjaga pemisahan logika yang bersih:

  • Global State (Context API): Menggunakan CartContext untuk mengelola isi keranjang belanja, FavoritesContext untuk daftar produk favorit, serta ThemeContext untuk pengaturan tema gelap dan terang yang tersimpan otomatis ke localStorage.
  • URL State: Parameter pencarian (q), filter kategori, pengurutan (sort), dan nomor halaman (page) disinkronkan langsung dengan URL menggunakan useSearchParams().
  • Server State: Data katalog, kategori, dan detail produk dari API dikelola dengan status siklus hidup loading, success, dan error.
  • Local & Form State: Mengatur galeri foto produk, modal checkout, notifikasi toast, serta input terkontrol (controlled components) dengan validasi pada formulir ulasan produk dan formulir checkout.

3. Data Fetching & API Service

Seluruh pemanggilan data eksternal dipisahkan ke dalam lapisan layanan src/services/productService.ts menggunakan fetch API yang terhubung ke DummyJSON Products API:

  • Caching & Pembatalan Request: Mendukung AbortController untuk mencegah race condition saat pengguna mengetik pencarian dengan cepat serta caching respons di memori.
  • Penanganan Kondisi UI: Dilengkapi komponen status LoadingSpinner / skeleton saat mengambil data, ErrorMessage dengan tombol coba lagi saat jaringan gagal, dan EmptyState ketika hasil pencarian kosong.

4. Custom Hooks & Reusable Components

Custom Hooks (src/hooks/):

  • useFetch: Hook generik untuk mengambil data asinkron lengkap dengan state loading, error, dan fungsi refetch.
  • useCart, useFavorites, & useTheme: Hook konsumen Context API untuk akses state global yang aman.
  • useLocalStorage, useDocumentTitle, & useSearchShortcut: Hook utilitas untuk persistensi penyimpanan browser, judul tab dinamis, dan pintasan keyboard.

Reusable Components (src/components/):

  • ProductCard, FavoriteButton, ReviewSection, RelatedProducts, UIStates, ToastContainer, dan BackToTop.

5. Struktur Folder (Separation of Concerns)

Kode diorganisasi berdasarkan tanggung jawab masing-masing lapisan arsitektur:

src/
├── components/   # Komponen UI reusable (ProductCard, UIStates, ReviewSection, dll.)
├── context/      # Global state menggunakan Context API (Cart, Favorites, Theme)
├── hooks/        # Custom hooks (useFetch, useCart, useLocalStorage, dll.)
├── layouts/      # Kerangka tata letak utama (MainLayout)
├── pages/        # Halaman rute aplikasi (Home, Products, ProductDetail, Cart, dll.)
├── services/     # Modul akses public API (productService.ts)
├── types/        # Definisi tipe data TypeScript (product.ts)
└── utils/        # Fungsi pembantu format harga dan notifikasi toast
